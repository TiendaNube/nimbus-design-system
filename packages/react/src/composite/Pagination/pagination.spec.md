## 1. What it solves

A user navigating a paginated list with many pages can move to any valid page by typing its number, on desktop and on mobile, instead of stepping one page at a time or choosing from the listed page numbers. Every text is translatable, so the component can be used by screen reader users in any language.

## 2. Scope

### In scope

- An optional "go to page" input beside `Pagination`'s existing arrow and number navigation.
- A compact first / previous / go-to-page / next / last layout, applied from the available width, that includes its own always-present go-to-page input.
- An input that only accepts digits and takes any number to the nearest valid page.
- Keeping the input's displayed value in step with page changes made through any other control.
- Accessible names, a navigation landmark, a current-page marker and a screen reader announcement of the page reached.
- Translatable texts through the `labels` prop.

### Non-goals

- Changing `Pagination`'s arrow and number navigation when the new input is not shown.
- Deciding whether `usePagination` and `DOTS` become public exports.
- Changing Nimbus's general guidance to prefer `InfiniteScroll` over `Pagination` on mobile.

## 4. Public API and contracts

### Props

| Prop | Type | Default | Required | Purpose |

| `renderItem` | function | — | optional | Existing, unchanged. |
| `showInput` | `boolean` | `false` | optional | The consumer opts in to the go-to-page input at the `md` breakpoint and wider (AC-02). |
| `labels` | `PaginationLabels` | `{}` | optional | Translatable texts (AC-20). |

### Events and callbacks

| Event | Payload | Trigger | Guarantees |
|---|---|---|---|
| `onPageChange` | `page: number` | Existing arrow and number clicks; go-to-page submission (AC-05); first and last controls (AC-10) | Called with an integer from 1 to `pageCount`; not called when the resulting page is the active page. |

### Defaults and precedence

1. `showInput` defaults to `false`: with no change to this prop, rendering at the `md` breakpoint and wider is unchanged.
2. Below the `md` breakpoint with `pageCount` of 6 or more, the compact layout and its input apply regardless of `showInput` (AC-03).
3. With `pageCount` below 6, `showInput` has no effect (AC-01).
4. Every text defaults to English (AC-20).

### HTML and form semantics

- Element or role: a text input for numeric entry; no `spinbutton` semantics (AC-13). The list sits inside a navigation landmark (AC-23).
- Form behavior: Not evaluated.
- Name and value behavior: the value mirrors `activePage` except while the user is editing (AC-09); it only ever holds digits (AC-21).
- Submission behavior: per AC-05; does not submit an enclosing form.
- SSR or hydration behavior: Not evaluated.

## 6. Responsive behavior

- Container behavior: from the `md` breakpoint (672px) the optional input sits beside the existing navigation (AC-02); below it the compact layout applies (AC-03).
- Small viewport behavior: per AC-03; the documented 360px minimum width for `Pagination` on mobile is unchanged.
- Content wrapping or truncation: the input's width follows its content (AC-07), so typed digits are not truncated.
- Width and height constraints: per AC-07; no fixed input width is part of this contract.
- Touch-specific behavior: the input opens a numeric on-screen keyboard (AC-13).
- Not applicable when: `pageCount` is below 6, where the existing navigation applies unchanged.

## 7. Accessibility

- Semantic role: a text input for numeric entry inside a navigation landmark.
- Accessible name: `labels.goToPage` for the input; `labels.navigation` for the landmark; the navigation controls per AC-12.
- Keyboard interaction: Enter submits (AC-05).
- Focus behavior: an `activePage` change does not move focus or overwrite typing (AC-09).
- Screen reader announcement: the page reached is announced after a submission and, in the compact layout, after a page change with the first, previous, next or last control (AC-19, AC-24). The "{of} {pageCount}" text is the input's description (AC-13).
- Disabled semantics: the disabled state of the navigation controls is exposed by the underlying button (AC-11).
- Error communication: Not applicable (AC-21).
- Contrast or motion requirements: Not evaluated.

## 9. Edge cases

- Long content: a `pageCount` with several digits is shown without truncation because the input follows its content (AC-07).
- Empty content: per AC-22.
- Dynamic content: the displayed value follows `activePage` (AC-09).
- Nested usage: Not evaluated.
- Right-to-left content: Not evaluated.
- Server-side rendering: Not evaluated.
- Other: a `pageCount` of exactly 6 is included in AC-01 and AC-03; a pasted number with more digits than `pageCount` goes to the last page (AC-14).

## 10. Compatibility and migration

- Backward compatibility: additive and opt-in at the `md` breakpoint and wider. Consumers already rendering `Pagination` below the `md` breakpoint with a `pageCount` of 6 or more see the compact layout in place of the page numbers. All consumers get a navigation landmark around the list.
- Public API impact: adds the `showInput` and `labels` props and the `PaginationLabels` type.
- Layout impact: per AC-03, for the case above.
- Accessibility impact: adds accessible names, a landmark, a current-page marker and an announcement.
- Migration required: none.
- Versioning impact: minor.
