# Pagination — Specification

- Source issue: #557
- Contract origin: candidate
- Last generated from: Discovery Decision Card (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5640785803), Triage (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5670372247), candidate spec (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5670399529), addendum 1 (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5703823940), addendum 2 (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5704157345), spec agreed to build (https://github.com/TiendaNube/nimbus-design-system/issues/557#issuecomment-5714953484)

## 1. What it solves

A user navigating a paginated list with many pages can move to any valid page by typing its number, on desktop and on mobile, instead of stepping one page at a time or choosing from the listed page numbers.

## 2. Scope

### In scope

- An optional numeric "go to page" input beside `Pagination`'s existing arrow and number navigation.
- A compact first / previous / go-to-page / next / last layout, applied from the available width, that includes its own always-present go-to-page input.
- Range validation, invalid-value feedback, and keeping the input's displayed value in step with page changes made through any other control.
- Accessible names for the previous, next, first, last and go-to-page controls.

### Non-goals

- Changing `Pagination`'s arrow and number navigation when the new input is not shown.
- Deciding whether `usePagination` and `DOTS` become public exports.
- Changing Nimbus's general guidance to prefer `InfiniteScroll` over `Pagination` on mobile.

## 4. Public API and contracts

### Props

| Prop | Type | Default | Required | Purpose |
|---|---|---|---|---|
| `activePage` | `number` | — | required | Existing, unchanged. |
| `pageCount` | `number` | — | required | Existing, unchanged. |
| `onPageChange` | `(page: number) => void` | — | required | Existing; also called by the go-to-page input (AC-05) and by the first and last controls. |
| `showNumbers` | `boolean` | `true` | optional | Existing, unchanged. |
| `renderItem` | function | — | optional | Existing, unchanged. |
| `showInput` | `boolean` | `false` | optional | The consumer opts in to the go-to-page input at the `md` breakpoint and wider (AC-02). |

### Events and callbacks

| Event | Payload | Trigger | Guarantees |
|---|---|---|---|
| `onPageChange` | `page: number` | Existing arrow and number clicks; go-to-page submission (AC-05); first and last controls (AC-10) | Called with an integer from 1 to `pageCount`; never for a value AC-04 rejects. |

### Defaults and precedence

1. `showInput` defaults to `false`: with no change to this prop, rendering at the `md` breakpoint and wider is unchanged.
2. Below the `md` breakpoint with `pageCount` of 6 or more, the compact layout and its input apply regardless of `showInput` (AC-03).
3. With `pageCount` below 6, `showInput` has no effect (AC-01).

### HTML and form semantics

- Element or role: a native number input; native spinbutton semantics apply.
- Form behavior: Not evaluated.
- Name and value behavior: the value mirrors `activePage` except while the user is editing (AC-09).
- Submission behavior: per AC-05; does not submit an enclosing form.
- SSR or hydration behavior: Not evaluated.

## 5. States and variants

| State or variant | Observable behavior | Relevant AC |
|---|---|---|
| Default | The input shows the current `activePage`. | AC-07, AC-09 |
| Focus | Native input focus ring. | AC-09 |
| Disabled (navigation controls) | First and previous are disabled on the first page; next and last are disabled on the last page. | AC-11 |
| Error | An invalid entry shows the input with the `danger` appearance and inline error text, and does not navigate. | AC-04, AC-06 |
| Empty | Not applicable: the input holds the active page unless the user clears it, which is an invalid entry (AC-04). | AC-04 |

## 6. Responsive behavior

- Container behavior: from the `md` breakpoint (672px) the optional input sits beside the existing navigation (AC-02); below it the compact layout applies (AC-03).
- Small viewport behavior: per AC-03; the documented 360px minimum width for `Pagination` on mobile is unchanged.
- Content wrapping or truncation: the input's width follows its content (AC-07), so typed digits are not truncated.
- Width and height constraints: per AC-07; no fixed input width is part of this contract.
- Touch-specific behavior: Not evaluated.
- Not applicable when: `pageCount` is below 6, where the existing navigation applies unchanged.

## 7. Accessibility

- Semantic role: native number input (spinbutton).
- Accessible name: "Go to page", static. The navigation controls are named per AC-12.
- Keyboard interaction: Enter submits (AC-05); the native number input keys apply.
- Focus behavior: an `activePage` change does not move focus or overwrite typing (AC-09).
- Screen reader announcement: the "of {pageCount}" text and the error message are associated with the input as descriptions (AC-13).
- Disabled semantics: the disabled state of the navigation controls is exposed by the underlying button (AC-11).
- Error communication: the error message is associated with the input as a description and the input is marked invalid while it is shown.
- Contrast or motion requirements: Not evaluated.

## 9. Edge cases

- Long content: a `pageCount` with several digits is shown without truncation because the input follows its content (AC-07).
- Empty content: Not applicable; see §5.
- Dynamic content: the displayed value follows `activePage` (AC-09).
- Nested usage: Not evaluated.
- Right-to-left content: Not evaluated.
- Server-side rendering: Not evaluated.
- Other: a `pageCount` of exactly 6 is included in AC-01 and AC-03.

## 10. Compatibility and migration

- Backward compatibility: additive and opt-in at the `md` breakpoint and wider. Consumers already rendering `Pagination` below the `md` breakpoint with a `pageCount` of 6 or more see the compact layout in place of the page numbers.
- Public API impact: adds the `showInput` prop.
- Layout impact: per AC-03, for the case above.
- Accessibility impact: adds accessible names to the navigation controls and the go-to-page input.
- Migration required: none.
- Versioning impact: minor.

## 12. What stays out

- Making `usePagination` and `DOTS` public exports of `@nimbus-ds/pagination`.
