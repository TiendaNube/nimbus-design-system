# ProgressRing — Specification

- Source issue: #533
- Contract origin: candidate
- Last generated from: Decision Card + domain decisions recorded for this run (see PR description for references)

## 1. What it solves

Consumers need to represent measurable, determinate completion progress in a compact circular format, with a visible value, at multiple sizes — a shape neither of Nimbus's existing progress primitives covers: `ProgressBar` is linear-only, `Spinner` is indeterminate-only.

## 2. Scope

### In scope

- Rendering determinate progress as a circular/ring shape with a visible, programmatically exposed value.
- Discrete size tokens.
- A required accessible name.

### Non-goals

- Replacing `ProgressBar` or extending `Spinner`'s indeterminate contract.
- Adopting `services-new-admin`'s specific implementation as this component's API.
- Interactive behavior — this is a non-interactive display primitive.
- Confirming demand beyond the Onboarding team.

## 3. Acceptance criteria

| AC | Criterion | Contract basis | Reference |
|---|---|---|---|
| AC-01 | The component accepts a required numeric `value` prop and clamps it to the range 0–100 | established | Domain decision (API-shape, Question 1); precedent `@nimbus-ds/progress-bar` |
| AC-02 | The component exposes `role="progressbar"` with `aria-valuenow` reflecting the clamped value, `aria-valuemin={0}`, and `aria-valuemax={100}` | established | Domain decision (API-shape, Question 2); precedent `@nimbus-ds/progress-bar` |
