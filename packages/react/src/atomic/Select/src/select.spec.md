# Select — Specification

- Source issue: #517
- Contract origin: initial baseline
- Last generated from: Discovery Decision Card, comment [`5456026317`](https://github.com/TiendaNube/nimbus-design-system/issues/517#issuecomment-5456026317) (`[Nimbus · Discovery]`); Lane and specification Stage Report, comment [`5456600501`](https://github.com/TiendaNube/nimbus-design-system/issues/517#issuecomment-5456600501) (`[Nimbus · Lane and specification]`); this Construction stage's own direct inspection of `nimbus-design-system` at `53b41f1`

## 1. What it solves

`Select` is a native-`<select>`-backed dropdown control with five visual appearance treatments
(four Figma-defined status variants — `neutral`, `success`, `warning`, `danger` — plus an
`ai-generative` treatment with no Figma-defined contract), and `Select.Skeleton` is its matching
loading placeholder. Both are meant to render at the same established height, so a resolving
skeleton does not shift surrounding layout.

## 2. Scope

### In scope

- `Select`'s four Figma-defined default appearances (`neutral`, `success`, `warning`, `danger`)
  rendering at the established 32px height (AC-05).
- `Select.Skeleton` rendering at the established 32px height (AC-06).
- `Select`'s core public contract (`name`/`id`/`children`/`appearance`/`aiGenerated`, native
  attribute pass-through, disabled/focus states), as this component's first baseline.

### Non-goals

- Defining a Figma contract for the `ai-generative` appearance (currently absent from Figma). A
  separate, future Design decision.
- Investigating or fixing `Input`'s possible parallel height discrepancy. Out of scope for #517;
  deferred pending a real measurement and, if confirmed, a separate issue.
- Standardizing the border-width literal-vs-token split (see §12).
- `Select.Group` and `Select.Option`'s own contracts. Not touched by #517.
- Any new variant, capability, or public prop.

listed as Nimbus-specific props.
