# Select — Specification

- Source issue: [#517](https://github.com/TiendaNube/nimbus-design-system/issues/517)
- Contract origin: initial baseline
- Last generated from: Decision Card comment [5444493152](https://github.com/TiendaNube/nimbus-design-system/issues/517#issuecomment-5444493152), Bootstrap fast-track (decision `0008`), 2026-08-27

## 1. What it solves

`Select` renders a native single-choice control (a styled `<select>`) with four semantic
appearances and an AI-generative variant. `Select.Skeleton` is its loading placeholder, shown
while the eventual set of options is not yet known, and must match `Select`'s footprint so the
loaded control does not shift the layout.

## 2. Scope

### In scope

- `Select`, its five `appearance` values (`neutral`, `success`, `warning`, `danger`,
  `ai-generative`), and the `aiGenerated` boolean override.
- `Select.Skeleton`.
- `Select.Group` and `Select.Option` only insofar as they are children rendered inside `Select`
  and do not affect its box model.

### Non-goals

- `MultiSelect` and its own skeleton — a related but separate component with its own source.
- The AI-generative visual treatment (gradient border, focus glow) beyond its box-model
  equivalence with the standard appearances (§4, §8).
- A redesign of `Select`'s visual language. This baseline only records what already exists; see
  §12 and the note in §8 on scope.

## 3. Acceptance criteria

- AC-01: `Select` renders at a total height of 32px for every `appearance` value (`neutral`,
  `success`, `warning`, `danger`, `ai-generative`), including when rendered via `aiGenerated`.
- AC-02: `Select.Skeleton` renders at a total height of 32px.
- AC-03: `Select` accepts `appearance` and renders the matching variant class; the default is
  `neutral`.
- AC-04: `Select` accepts `aiGenerated`; when `true`, it takes precedence over `appearance` and
  renders the AI-generative treatment with its focus glow.
- AC-05: `Select` renders `name`, `id`, and its `children` (`Select.Group`/`Select.Option`) on the
  native `<select>` element.
- AC-06: `Select` shows a trailing chevron icon, absolutely positioned and non-interactive
  (`pointer-events: none`), that does not affect the control's height.
- AC-07: A `disabled` `Select` shows a distinct border, background, text color, and
  `cursor: not-allowed`, and does not change height.
- AC-08: A focused `Select` shows a visible focus ring (`box-shadow`) via `:focus-visible`, and
  does not change height.
- AC-09: `Select.Skeleton` accepts `width`, defaulting to `15rem`, and a fixed `0.5rem`
  `borderRadius`.

## 4. Public API and contracts

### Props

| Prop | Type | Default | Required | Purpose |
|---|---|---|---|---|
| `name` | `string` | — | Yes | Name of the native `<select>` element |
| `id` | `string` | — | Yes | Id of the native `<select>` element |
| `children` | `ReactNode` | — | Yes | `Select.Group`/`Select.Option` content |
| `appearance` | `"neutral" \| "success" \| "warning" \| "danger" \| "ai-generative"` | `neutral` | No | Visual style; every value shares the same height contract (AC-01) |
| `aiGenerated` | `boolean` | `false` | No | Forces the AI-generative treatment with an active focus glow, overriding `appearance` |
| ...rest | `SelectHTMLAttributes<HTMLSelectElement>` | — | No | Passed through to the native `<select>` |

`Select.Skeleton` props:

| Prop | Type | Default | Required | Purpose |
|---|---|---|---|---|
| `width` | `SkeletonProps["width"]` | `15rem` | No | Placeholder width |
| `className` | `string` | — | No | Passed through to `Skeleton` |
| `data-testid` | `string` | — | No | Passed through to `Skeleton` |

Every prop above is already public and in use; this baseline does not add or remove any.

### Events and callbacks

Not applicable — `Select` forwards native `<select>` DOM event props (e.g. `onChange`) through
`...rest`; it defines no callback of its own.

### Defaults and precedence

1. `aiGenerated={true}` takes precedence over `appearance` (AC-04).
2. `appearance` defaults to `neutral` when neither is set.

### HTML and form semantics

- Element or role: native `<select>` (implicit `combobox`/`listbox` semantics from the browser).
- Form behavior: participates in native form submission via `name`; no Nimbus-specific handling.
- Name and value behavior: native — governed by `<option>`/`<optgroup>` children.
- Submission behavior: native.
- SSR or hydration behavior: not evaluated in this baseline — no SSR-specific code path was found.

## 5. States and variants

| State or variant | Observable behavior | Relevant AC |
|---|---|---|
| Default (`neutral`) | 32px height, 1px solid border, neutral colors | AC-01, AC-03 |
| `success` / `warning` / `danger` | Same height and box model as `neutral`; only border/background color change | AC-01, AC-03 |
| `ai-generative` / `aiGenerated` | Same height and box model as the standard appearances; gradient border and, when `aiGenerated`, an active focus glow | AC-01, AC-04 |
| Hover | Not applicable — no `:hover` rule exists on `Select`'s base or appearance styles |
| Focus | Visible `box-shadow` focus ring via `:focus-visible`; border color changes via `:focus` on some appearances | AC-08 |
| Disabled | Distinct border/background/text color, `cursor: not-allowed`; height unchanged | AC-07 |
| Loading (`Select.Skeleton`) | 32px height, matching the loaded control | AC-02 |
| Error | Not applicable — `Select` has no dedicated error state beyond the `danger` appearance |
| Empty | Not evaluated — behavior with zero `<option>` children was not exercised in this baseline |

## 6. Responsive behavior

- Container behavior: `width: 100%` — fills its container; height is fixed at 32px regardless of
  container width.
- Small viewport behavior: not evaluated in this baseline.
- Content wrapping or truncation: not evaluated — native `<select>`/`<option>` text overflow
  behavior is browser-controlled.
- Width and height constraints: height is fixed (32px, §8); width is fluid.
- Touch-specific behavior: not evaluated.
- Not applicable when: n/a.

## 7. Accessibility

- Semantic role: native `<select>` (browser-native `combobox` semantics); no ARIA is added.
- Accessible name: derived natively from an associated `<label>` via `id`, or `aria-label`/
  `aria-labelledby` passed through `...rest` — not enforced by `Select` itself.
- Keyboard interaction: native browser `<select>` keyboard handling; not modified.
- Focus behavior: native tab order; visible focus ring via `:focus-visible` (AC-08).
- Screen reader announcement: native.
- Disabled semantics: native `disabled` attribute passed through `...rest`; paired with the visual
  state in AC-07.
- Contrast or motion requirements: not evaluated in this baseline.

## 8. Contractual tokens and Design constraints

| Contract | Expected value or behavior | Relevant AC |
|---|---|---|
| `Select` total rendered height, every appearance | `2rem` (32px) | AC-01 |
| `Select.Skeleton` total rendered height | `2rem` (32px) | AC-02 |
| `ai-generative` shares `Select`'s sizing code path | Confirmed: `appearance["ai-generative"]` composes the same `base` style object as the four standard appearances and only overrides border/background — it is not a separate implementation | AC-01, AC-04 |

Evidence for the 32px value: Figma file `TDwgeblsVNeHKKRvoDRk7n` ("☁️ Nimbus DS - Tokens &
Components"), page "🧩 Atomic components / Select" — `absoluteBoundingBox.height = 32` on the
`Select` variant nodes (`6526:184086`, `6526:184090`, `6526:184094`, `9066:17807`, covering all
four standard appearances) and on the `Select.Skeleton` instance node (`6535:183336`), verified
directly via the Figma REST API and recorded on issue #517 (Decision Card, comment
5444493152). Recorded here as an established contract per an explicit human decision (the
requester, 2026-08-27), not inferred from the implementation that existed before this fix — see
the note on baseline fidelity below.

Note on scope: this value replaces two implementation accidents that were never a recorded
contract — `Select`'s previous 34px (`padding` `spacing[2]` × 2 + `lineWeight.body.caption` +
1px border × 2, none of which were chosen to sum to a specific total) and `Select.Skeleton`'s
previous 36px (a flat hardcoded `2.25rem` unrelated to `Select`'s own box model). Neither
implementation value is carried into this baseline as a guarantee, per 0009 and the specification
template's own quality rule against turning an implementation accident into a guarantee.

## 9. Edge cases

- Long content: not evaluated — native `<option>` text handling.
- Empty content: not evaluated — behavior with zero children was not exercised.
- Dynamic content: not evaluated.
- Nested usage: `Select` is composed once elsewhere in this package, inside
  `FormField.Select` (`packages/react/src/components/FormField/src/components/FormFieldSelect/FormFieldSelect.tsx`),
  which renders `Select` unchanged inside `FormField`'s own wrapper and does not alter its box
  model.
- Right-to-left content: not evaluated.
- Server-side rendering: not evaluated (see §4).
- Other: `Select.Group` and `Select.Option` render inside `Select`'s native `<select>` and do not
  affect its height.

## 10. Compatibility and migration

- Backward compatibility: the rendered height changes (34px → 32px for `Select`; 36px → 32px for
  `Select.Skeleton`). No prop, event, or markup structure changes.
- Public API impact: none — no prop added, removed, or retyped.
- Layout impact: yes, by design — this is the fix. A consumer that hardcoded pixel offsets
  against the old 34px/36px heights may need to adjust; none were found in this repository search
  (§9, nested usage).
- Accessibility impact: none identified.
- Migration required: no code change required for consumers.
- Versioning impact: patch.
